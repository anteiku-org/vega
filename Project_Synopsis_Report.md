## 1. Abstract
This project focuses on the design, development, and testing of a custom flight controller using the ESP32 microcontroller. While many off-the-shelf flight controllers exist, developing a custom solution offers profound insights into real-time operating systems, sensor fusion, PID control loops, and autonomous navigation. The proposed system integrates an ESP32 DevKit V1 with an MPU6050 (6-axis Inertial Measurement Unit), a BMP280 (Barometric Pressure Sensor), a GPS module, and a LoRa radio module for long-range telemetry. By implementing custom firmware in C/C++, this flight controller will be capable of achieving stable flight, altitude hold, and waypoint navigation. The project aims to provide an open-source, low-cost, and highly extensible platform for unmanned aerial vehicles (UAVs).

## 2. Introduction

### A) Overview
Unmanned Aerial Vehicles (UAVs) have become integral in various sectors, including agriculture, surveillance, and logistics. The "brain" of any UAV is its flight controller, which continuously reads sensor data, computes necessary adjustments, and outputs signals to the Electronic Speed Controllers (ESCs) to maintain stability. This project involves building a flight controller from scratch using the powerful dual-core ESP32 microcontroller, which offers built-in Wi-Fi and Bluetooth, making it a versatile choice for modern IoT-enabled UAVs.

### B) Prior Work (Literature Review)
Existing open-source flight controller firmware like Betaflight, ArduPilot, and INAV have set high standards in the drone industry. Most of these platforms traditionally rely on STM32 microcontrollers. However, recent research has explored the ESP32 as a viable alternative due to its high clock speed (240 MHz) and dual-core architecture, which allows one core to handle time-critical PID calculations and the other to manage communications (telemetry and networking). Studies on complementary filters and Kalman filters for MPU6050 have shown that high-accuracy attitude estimation is achievable on low-cost hardware.

### C) Challenges
- **Real-Time Processing:** Achieving a consistent and high loop-time for PID calculations without being interrupted by other processes.
- **Sensor Noise:** The MPU6050 and BMP280 are susceptible to mechanical vibrations from the motors, requiring robust digital low-pass filtering.
- **Sensor Fusion:** Accurately combining accelerometer and gyroscope data to avoid drift and calculate absolute orientation (pitch, roll, and yaw).
- **Power Delivery:** Providing a stable 3.3V supply to the sensors while isolating them from the high-current noise generated by the ESCs and motors.

### D) Motivation
The motivation behind this project is to demystify the complex algorithms that govern drone flight. By building a custom flight controller rather than purchasing a pre-configured one, we gain hands-on experience in control systems, sensor calibration, embedded C programming, and hardware integration. Furthermore, using an ESP32 opens up possibilities for remote telemetry and web-based ground control stations.

### E) Objective
- To design and assemble a hardware platform integrating ESP32, MPU6050, BMP280, GPS, and LoRa.
- To implement I2C communication protocols to reliably read sensor data.
- To develop sensor fusion algorithms (e.g., Mahony or Madgwick filters) for accurate attitude estimation.
- To implement and tune a PID controller for stable multirotor flight.
- To establish long-range telemetry communication using the LoRa module.

## 3. Requirement Analysis

### A) Functional Requirement
- The system must read pitch, roll, and yaw rates at a minimum of 250Hz.
- The system must calculate PID corrections and output PWM signals to 4 ESCs.
- The system must receive RC (Radio Control) commands or autonomous waypoints.
- The system must transmit telemetry data (altitude, orientation, GPS coordinates) to a ground station via LoRa.

### B) System Requirement
- **Control Loop Rate:** Minimum 250Hz (4ms loop time).
- **Communication Protocol:** I2C for IMU and Barometer; UART for GPS and SPI for LoRa.
- **Failsafe:** The system must cut power to the motors if the communication link is lost.

### C) Hardware Requirement
- Microcontroller: ESP32 DevKit V1
- IMU: MPU6050 (3-axis Gyroscope + 3-axis Accelerometer)
- Barometer: BMP280 (for altitude hold)
- Communication: LoRa Transceiver Module (e.g., SX1278), RC Receiver
- Navigation: GPS Module (e.g., Ublox NEO-6M)
- Actuation: 4x Electronic Speed Controllers (ESCs) and Brushless DC Motors
- Power: Lithium Polymer (LiPo) Battery and Power Distribution Board (PDB) with 5V/3.3V BEC.

### D) Software Requirement
- Programming Environment: Visual Studio Code with PlatformIO or Arduino IDE.
- Language: C/C++
- Libraries: Wire (I2C), standard SPI, custom or open-source PID and IMU libraries.
- Ground Control Station: Custom web interface or QGroundControl (via MAVLink).

## 4. Feasibility Analysis

### A) Technical Feasibility
The ESP32 possesses dual cores running at 240 MHz, which is more than sufficient for running real-time flight dynamics on one core while handling Wi-Fi/Bluetooth or LoRa telemetry on the other. The chosen I2C sensors (MPU6050 and BMP280) are well-documented with extensive community support, making the hardware integration highly feasible.

### B) Scheduling Feasibility
The project is divided into distinct phases: Hardware assembly, I2C sensor interfacing, sensor fusion, PID implementation, and flight testing. With a structured approach over the semester, this timeline is realistic. Core flight stability will be prioritized before adding advanced features like GPS navigation.

### C) Financial Feasibility
The components selected are extremely cost-effective. The ESP32, MPU6050, and BMP280 are low-cost modules readily available in the market. The primary costs will be the drone frame, motors, ESCs, and LiPo battery, which fall well within a standard student project budget.

### D) Social and Ethical Consideration
The project will strictly adhere to local drone regulations regarding flight altitude, line-of-sight operation, and no-fly zones. The system will include safety mechanisms, such as an automatic motor kill-switch (failsafe) to prevent injury or property damage in case of software malfunction or signal loss.

## 5. Methodology

1. **Hardware Integration:** 
   - Designing the schematic and wiring the ESP32 to the MPU6050, BMP280, LoRa, and GPS.
   - Ensuring safe voltage levels (3.3V for sensors).
2. **Firmware Development - Phase 1 (Sensors):**
   - Writing code to read raw data from the MPU6050 and BMP280 via the I2C bus (Pins 21 and 22).
   - Implementing low-pass filters and calibration routines to eliminate sensor offsets.
3. **Firmware Development - Phase 2 (Control):**
   - Implementing the Madgwick or Mahony filter to convert raw IMU data into Euler angles (Pitch, Roll, Yaw).
   - Developing the PID control loop to calculate motor output based on the error between the desired orientation (from the RC receiver) and the actual orientation.
4. **Firmware Development - Phase 3 (Actuation & Telemetry):**
   - Configuring the ESP32 hardware timers to generate precise PWM signals for the ESCs.
   - Integrating the LoRa module to send real-time telemetry back to a ground station.
5. **Testing and Tuning:**
   - Testing the drone on a single-axis test bench to safely tune the Proportional (P), Integral (I), and Derivative (D) gains.
   - Conducting tethered flight tests before attempting free flight.
